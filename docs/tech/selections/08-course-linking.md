# 选型八：回答与课程的关联

> 所属：[Keine Explore Harness v1](../Keine_explore_harness_v1.md) · 附录 D
>
> 结论：**作答之后，在同一次运行内关联课程：按课程版本的概念索引做规范化字符串匹配召回候选，由模型在只开放 `link_course` 的一步里筛选并说明，链接由服务端按索引条目生成。只在岔出新节点的那一轮做。**

---

## 1. 问题

后续轮先作答（选型六），课程不再构成回答的范围。分支节点和发散节点因此能走出本讲，但读者也失去了「这个回答和课程里哪里有关」的线索。

需要面对的事实：

- **先给课程就框住回答**：任何在作答前注入课程内容的做法，都会把回答拉回课程；
- **读者已经读到回答**：回答是流式输出的，事后改写正文会替换读者已经读过的内容；
- **字面相同不等于相关**：同一个词在不同讲里可能讲的不是一回事；
- **链接必须真实**：讲和小节的位置不能由模型编写；
- **成本**：每一轮多一次运行，或多一套嵌入设施，都会长期累积。

## 2. 评估维度

| 维度 | 说明 |
| --- | --- |
| 回答范围 | 关联是否影响回答本身 |
| 准确性 | 误命中能否被剔除，关联是否带有说明 |
| 链接可信 | 位置是否由系统生成 |
| 成本 | 额外的模型调用、存储和设施 |
| 读者体验 | 关联是否替换已读内容，是否在同一次等待内完成 |

## 3. 候选方案

### 3.1 方案 A：作答前按问题检索课程

```mermaid
flowchart LR
  Q["提问"] --> K["检索课程片段"] --> C["背景 + 片段 + 历史"] --> M["作答"]
```

| 优势 | 劣势 |
| --- | --- |
| 回答能直接引用课程内容 | 课程又成了回答的开头和范围 |
| — | 每一轮的检索结果不同，破坏前缀缓存 |

### 3.2 方案 B：作答后单独运行一次，重写回答

```mermaid
flowchart LR
  M["作答"] --> R["第二次运行<br/>带课程内容重写"] --> N["替换后的回答"]
```

| 优势 | 劣势 |
| --- | --- |
| 关联可以融入正文 | 替换读者已经读到的内容 |
| — | 多计一次运行，等待时间翻倍 |

### 3.3 方案 C：只做字符串匹配，直接标成链接

```mermaid
flowchart LR
  M["作答"] --> X["匹配概念索引"] --> L["命中的概念标为链接"]
```

| 优势 | 劣势 |
| --- | --- |
| 不调用模型，最便宜 | 误命中无法剔除 |
| 实现简单 | 说不出那一讲的内容和这里的回答有什么关系 |

### 3.4 方案 D：模型抽取或向量相似度召回

```mermaid
flowchart LR
  M["作答"] --> E["模型抽取概念<br/>或计算向量"] --> S["相似度检索"] --> F["筛选"]
```

| 优势 | 劣势 |
| --- | --- |
| 召回更好，同义改写也能命中 | 多一次调用，或多一套嵌入模型和向量存储 |
| — | 候选的来由不透明，难以测试 |

### 3.5 方案 E：作答后同一次运行内，索引召回、模型筛选（选定）

```mermaid
flowchart LR
  M["自由作答"] --> X["规范化字符串匹配<br/>概念索引，最多 5 条"]
  X --> L["关联步骤<br/>只开放 link_course"]
  L --> R["服务端按索引条目<br/>生成课程关联"]
```

| 优势 | 劣势 |
| --- | --- |
| 回答不受影响，关联附在回答之后 | 召回依赖名称和别名的字面出现 |
| 误命中由模型剔除，每条关联带一句说明 | 需要为每个课程版本建立概念索引 |
| 位置来自索引，链接真实 | 关联步骤多一次模型调用（同一次运行内） |
| 不需要嵌入设施，候选可预测、可测试 | — |

## 4. 对比矩阵

| 维度 | A 先检索 | B 重写 | C 只匹配 | D 向量召回 | **E 召回 + 筛选** |
| --- | --- | --- | --- | --- | --- |
| 回答范围 | 被框住 | 被改写 | 不影响 | 不影响 | **不影响** |
| 准确性 | — | 高 | 低 | 高 | **高** |
| 链接可信 | 模型编写 | 模型编写 | ✓ | ✓ | **✓** |
| 成本 | 每轮检索 | 多一次运行 | 最低 | 多一次调用或设施 | **一次关联调用** |
| 读者体验 | — | 替换已读内容 | 好 | 好 | **好：同一次等待内完成** |

## 5. 结论与选择原因

选定：**方案 E，作答后在同一次运行内，按概念索引召回、由模型筛选**。

1. **回答先于关联。** 模型照常自由作答；关联只追加在回答之后，读者已读的内容不变。
2. **召回便宜、可预测。** 概念名和别名在规范化（兼容形式折叠、小写、去空白）后做子串匹配；选区所在那一讲排除在外；按首次出现排序，最多 5 条。
3. **筛选交给模型。** 关联步骤只开放 `link_course`，要求模型判断候选是否真正相关、并写出关系；字面相同而含义不同的候选被剔除。
4. **链接由系统生成。** 模型只给候选标识和说明，讲和小节的位置取自索引条目。
5. **只在岔出那一轮做。** 岔出点是读者改变方向的地方，关联在这里最有价值；节点里之后的轮次由模型自己组织，避免每一轮都多一次调用。
6. **索引成本可控。** 概念索引按课程版本由管理员手动建立，没改动的讲沿用上一版的条目；索引未建立时照常作答，只是不做关联。
