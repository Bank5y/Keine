# 探索对话的节点是独立的实体，轮次仍是父指针树

探索对话分主节点、子节点、分支节点、发散节点，卡片上要显示节点数。主流的多分支对话（pi、LibreChat、Open WebUI、ChatGPT 导出格式）只有一棵消息树：每条消息带父指针，所谓「分支」只是从根到某个叶子的一条路径，没有实体，也没有类型。我们保留这种存储，每一轮的父指针指向上一轮，上下文从当前位置沿父指针走到根再反转。在它上面再加一层**节点**实体：节点有稳定的 ID、类型、岔出点（父节点的哪一轮）和可选的选中片段，节点内部的轮次只能线性往下接，要分叉只能开一个带类型的新节点。

这样做是因为节点类型、类型对应的默认初始提示词、选中片段、节点数，「按节点同步回探索文档」，以及以后的「引用其他节点」，都需要一个能指名的对象。纯消息树里没有地方放这些东西，硬加就只能在每段的第一条消息上打标记，靠遍历推断出节点边界，等于在消息树上手工拼出这里的节点。存储和上下文组装仍然照搬成熟做法，同一祖先链上的节点共享前缀，可以命中提示词缓存。

## Considered Options

- **纯消息树，分支 = 路径（pi 原样）**：最简单，在任何一条消息后都能分叉。但没有分支对象，类型、节点数、默认提示词、引用对象都没有归属；随处可分叉，还会长出没有类型的杂枝，和「分叉只来自带类型的节点操作」冲突。
- **复制成新对话（pi `/fork`、ChatGPT「Branch in new chat」、SillyTavern）**：分支之间互不干扰，但一个探索会变成多份对话，前缀要复制，来源只能靠 ID 或文件名回指，和「一个探索一棵对话树」不符。

## Consequences

- 节点内部线性：同一节点里，一轮最多有一个属于同一节点的后继。第一版没有「编辑提问 / 重新生成」产生的兄弟版本，失败重试原地替换；以后要加，得先想清楚它属于哪个节点。
- 新节点只看到岔出点为止的祖先链，父节点在岔出点之后的内容、兄弟节点都不进入上下文；跨节点的信息第一版只通过探索文档流动。
- 所有类型的节点在结构上相同：同样的字段、同样的存储和上下文组装、同样的嵌套规则、工具集和步数上限。类型只是节点上的一个标签，只决定默认初始提示词，并作为同步时的参考提示，代码里用一张「类型 → 默认初始提示词、同步提示」的表表达，不按类型分出不同的节点实现。主节点的特殊之处（唯一、固定时由系统创建、不能删除、没有岔出点）来自它是树根，不来自类型。
- 默认初始提示词：读者可以修改，改后的文字作为节点第一条提问保存，不进系统提示词，所以前缀缓存不受影响。
- 同步写进探索文档的哪一段由内容决定，不由节点类型决定，见下面的补充。
- 当前看的是哪个节点、哪一轮，由请求带上，服务端不保存会话状态。
- 提问消息带一个有种类的附件列表，第一版只有「选中片段」；以后「引用其他节点」作为新的附件种类加入。pi 的 `branch_summary`（另一条路径的摘要作为一条消息插入）是候选形态之一。

依据见 `research/branching-dialogue` 分支的调研报告，以及「探索对话的节点模型」（#100）里对 pi（`earendil-works/pi` @ `edfe6b2`）的调查。

## 补充：探索文档的段落和按内容同步（#113）

> 已被 ADR 0012 取代：探索文档只有标题、概念、概念解释三段，同步取消，改为生成探索报告。下面保留原文，供追溯。

探索文档的段落由代码固定：标题、简介、含义、延伸、扩展、参考，模型只写内容、不写段名。分析只生成前三段；含义里不再分小标题，先解释概念本身，再结合这一讲说明它在这里的角色。延伸（课程内其他讲或小节，有序）、扩展（课程外相似但不相关的内容，无序）、参考（标题加链接）和挂在含义某一句上的脚注都是独立存储的项，每一项记录它来自哪个节点的哪一轮，有内容时才出现。

同步不再按节点类型决定写到哪里：读者开的节点类型不一定和他实际问的内容一致（开了子节点，问的却是别的架构下的广度问题），按类型硬写会把内容放错位置。同步是一次不带工具的运行，用「同步」技能的提示词，节点类型只作为一条参考提示；它对照当前探索文档的全部内容和每一项的来源，输出一组按段分开的修改块：改写含义（必须保留先概念、后本讲的写法）、新增或替换脚注、延伸、扩展、参考。每块要么新增，要么替换已有的某一项；只能替换来自从这一轮上溯到主节点那条链路的项，兄弟分支的内容只读，服务端校验。读者逐块勾选后一起应用，第一版不能在面板里编辑。

参考只在读者要求时补充（同步面板上的「补充参考」，或这一轮里读者明确要求），条目只能来自链路上各轮的来源清单，由服务端生成和校验，模型不手写链接。脚注用文本引用定位到含义里的一句，含义被改写后重新定位，定位不上的挂在含义末尾、不删除。

这取代了上面原来「类型决定同步目标、同一节点替换自己那一份」的写法，以及「探索对话的结果怎么同步回探索文档」（#108）的第 4、5、7 条和第 8 条里的整份差异。没有保留按类型绑定，是因为节点类型由读者选，不能当作内容分类的依据；没有让读者自由选段，是因为那样文档会失去固定结构。
