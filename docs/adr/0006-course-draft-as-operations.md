# 编辑稿记录操作而不是快照，提交时在最新版本上重新应用

课程编辑页上的修改先累积在服务器上的一份编辑稿里，提交时作为一次课程更新生效，或者成为一份更新申请。编辑稿存的是一步步的操作，例如「把某讲移到某章」「替换某讲」「删除某章」，而不是编辑后整门课的快照。提交时，这些操作按顺序应用到课程的**最新**版本上。课程在编辑期间没有变化时，结果和快照一样；如果别人的更新或整包更新已经先生效，能应用的操作照常应用，应用不了的（例如要替换的讲已被删除）逐条列给用户确认，不会悄悄覆盖别人的改动。

## Considered Options

- 存快照，基于旧版本：实现简单，但提交时会把编辑期间别人生效的更新整个覆盖掉，或者只能整份作废，让用户从头再改。
- 编辑即生效，不要编辑稿：每个小操作都是一次课程更新，订阅者会收到一连串通知，标注也会被反复迁移；公开课程的每一步还都要单独审核。

## Consequences

- 每种操作都要能在「它针对的章或讲已经变了」时判断能否应用，并给出说明。
- 撤销就是去掉最后一个操作，不需要另存历史。
- 编辑稿里上传的讲文件放在编辑稿自己的临时区域，提交时进入新版本（ADR-0005），放弃或过期时删除。
- 编辑稿成为更新申请时，申请也保存其中能应用的操作。批准时这些操作在课程的最新版本上重新应用，不会覆盖申请提交后生效的其他更新；有操作已无法应用的申请不能批准，只能驳回，由申请人重新提交。
