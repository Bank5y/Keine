# 后续轮先作答，再在同一个 loop 里关联课程

> 第 2 步的召回方式已被 [ADR 0015](0015-concept-index-hybrid-recall.md) 取代；Considered Options 最后一条（不引入嵌入）同样不再成立。

`followup-1` 在每一轮最前面带上课程信息、课程目录、选中的原文和本讲全文，再加上带标签的首轮回复和一条「【当前探索文档】」消息。模型因此把课程当成回答的范围：子节点、分支节点、发散节点的回复都绕回本讲，反复出现「本文档中」「基于本课程」这类说法（#154）。

我们改成**先作答，再关联**。后续轮的上下文只剩课程信息、选中的原文、首轮问答（问句加去掉标签的 Markdown 分析）和沿祖先链的历史，不再带课程目录、本讲全文和探索文档。模型需要课程内容时，自己用工具去读。节点类型不再表示范围（课程内或课程外），只表示作答方向。节点说明只写进岔出那一轮的提问里，措辞只约束「此次作答」；读者在节点里接着聊，就不再重复提示。

跟课程的关联只在岔出那一轮做，并且在同一个 loop 里完成：

1. 模型照常自由作答，课程工具和网络工具都能用。
2. 模型给出不带工具调用的回答后，harness 不结束运行，而是用概念索引里的概念名和别名，对回答做规范化的字符串匹配。选区所在那一讲的条目排除在外，最多取 5 条候选。
3. 有候选时，harness 往 loop 里追加一条消息，内容是这些候选和它们对应小节的正文，并且只开放 `link_course` 一个工具，参数是 `[{entry, note}]`，可以为空。
4. 模型调用 `link_course` 后运行结束。harness 根据参数和索引条目，确定性地渲染出「课程里的相关内容」，链接由系统生成。

概念索引按课程版本建立，由管理员在管理页手动建立，费用记在站点上。没改动的讲沿用上一版的条目。索引还没建立时，岔出那一轮照常作答，只是不做关联。

## Considered Options

- **保持先注入、后作答（`followup-1`）**：模型手边信息最全，但正是这种做法把回答框在了课程里。只靠提示词去抵消注入内容的分量，效果不稳定。
- **作答前先按问题检索课程（RAG）**：回答依然由课程内容开头，和现在的问题一样。
- **作答后再单独调一次模型，重写整段回答**：读者已经读到的内容会被替换掉，还要多计一次运行。
- **不调模型，只把命中的概念标成链接**：最便宜，但做不到把那一讲的内容和这里的回答联系起来，误命中也没有机会筛掉。
- **用模型抽取概念或向量相似度来匹配**：召回更好，但要多一次调用或多一套嵌入设施。字符串匹配召回的候选，在第 3 步由模型筛选，已经够用。

## Consequences

- 前缀缓存仍然成立：系统提示词、回答风格模块和背景每一轮都一样；节点说明属于岔出那一轮的提问，重建历史时原样带上。
- 一轮回复由两部分组成：自由作答的文本，以及可能存在的、结构化的课程关联。界面在第 3 步显示「正在关联课程内容…」。
- 只有岔出那一轮做关联。节点里之后的轮次，以及主节点第 2 轮以后的轮次，都由模型自己组织。工具不按节点类型裁剪。
- 存下的旧回复不清洗。提示词里不写「后续所有」「必须」这类分量过重的说法。
- 措辞、语气、禁用的元叙述等，放进可替换的回答风格模块，默认面向计算机内容。每一轮的元数据记下风格的 id 和版本。
