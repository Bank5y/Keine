# 探索文档固定后不变，探索报告取代同步

ADR 0009 的补充设计了「同步」：读者在探索对话的某一轮上发起同步，助手把讨论结果按段改进探索文档，包括改写含义，新增或替换脚注、延伸、扩展、参考；读者逐块确认，可以撤销。这让探索文档身兼两职：既是阅读页侧边卡片上那个简短的概念说明，又是对话深入之后的成果汇总。修改块、条数上限、链路校验、修订和撤销，都是为了让一份文档承担这两件事而付出的代价。

我们把两件事分开：

- **探索文档**只有标题、概念、概念解释三段，由分析生成，固定后不再变化。它就是分析的结果，在阅读页上保持最小精简。
- **探索报告**是读者在探索对话里点「生成探索报告」后，由探索助手读完整棵对话树写出的说明文档，挂在探索名下，每生成一次多一个版本，并记下这一版纳入了哪些轮次。它按技术说明文档来组织：标题、摘要、正文（小节由内容决定）、要点、参考。它不按课程的讲组织，也不写「第几讲」。参考由系统根据实际查阅过的来源记录生成。报告只读，可以下载为 Markdown。

## Considered Options

- **保留同步**：探索文档和对话始终一致，但要维护修改块协议、条数上限、链路校验和修订，文档结构还会随着同步变得越来越长，侧边卡片上也放不下了。
- **一次性导出 Markdown 文件，不保存**：最简单，但读者掌握不了自己生成过的内容，以后也没法做「标记已参与生成的轮次」「手动选节点」。
- **不调模型，把对话按树的顺序拼起来导出**：免费、忠实，但只是一份对话记录，算不上文档。

## Consequences

- 探索文档的脚注、延伸、扩展、参考四段连同存储一起去掉（它们从来没有被写入过）。#138 同步关闭，#82 手动编辑探索文档关闭。
- 后续轮的上下文不再单独带探索文档：文档就是首轮分析，而首轮问答已经在上下文里了（ADR 0011）。
- 生成报告不算探索对话的一轮，不进对话树，也不能被岔出；照常扣读者积分，在用量里单独一类，提示词版本从 `report-1` 开始。
- 整棵树超长时，第一版直接拒绝，不扣积分。压缩提示和压缩注入作为后续待办。
- 跨节点的信息以前通过探索文档流动（ADR 0009）；现在不再流动，只在生成报告时汇总。
