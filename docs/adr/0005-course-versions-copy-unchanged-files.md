# 新版本只上传改过的文件，没改的从旧版本复制

课程的每个版本仍是一份完整的文件目录（ADR-0001、ADR-0004 都依赖这一点）。但编辑稿往往只替换一两讲，为此把整门课的文件、包括视频重写一遍不可接受。所以存储接口增加一个「复制」操作：S3 上用服务端复制，本地磁盘用硬链接，都不搬运数据。生成新版本时，改过或新增的文件照常写入，没改的文件从当前版本目录复制过去。

## Considered Options

- 按内容寻址（每个文件按哈希存一份，版本只是「路径 → 文件」的表）：最省空间，但要重做存储布局、下架冻结、清理和更新申请，改动太大。
- 维持现状（每次都写完整目录）：实现最简单，但一门带视频的课替换一讲就要重写几个 GB。

## Consequences

- 每个版本目录仍然自成一体，冻结、清理、更新申请的逻辑不变。
- 本地存储要求新旧目录在同一个文件系统上（硬链接的前提）；做不到时退回真正的复制。
- 整包更新的行为不变，它本来就带着全部文件。
