# 探索助手在 Go 进程内运行，工具循环归 Keine，可替换的只有模型适配器

探索助手的工具循环（调模型 → 执行工具 → 回填结果 → 再调模型）写在 Keine 的 Go 服务里，不用 agent 框架的整套循环，也不另起 sidecar 进程。能替换的单位是**模型适配器**：它只负责一次流式调用，把各家的流式增量拼装好，向上交出文本增量、完整的工具调用、统一后的用量（输入、输出、缓存命中、缓存写入）和结束原因。工具执行和权限、运行中的进度事件、轮数上限、截止时间、取消、每一步的用量计量、输出校验都在循环里，由 Keine 决定。这样数据库里的消息、推给前端的事件、工具定义三条边界都是 Keine 自己的格式，换服务商或换框架只动适配器。

## 边界

- **保存的消息**：和服务商无关，角色加 Markdown 内容，元数据记模型、提示词版本和用量，以带格式版本号的 JSON 存储。运行中的工具调用和工具结果只在内存里，不落库；系统提示词不保存原文，只记版本。
- **流式事件**：`POST` 请求，响应为 `text/event-stream`，事件只有 Keine 定义的 `delta`、`activity`、`done`、`error`，服务商的原始片段一律不透传。连接断开即取消运行，已消耗的用量照样计入，第一版不做续接。
- **工具和技能**：工具是 Keine 的 Go 接口（名称、描述、从 Go struct 生成的入参 JSON Schema、`Execute`），只能通过运行上下文（用户、课程、讲、选区）访问数据，权限由 Keine 保证；适配器负责转换成各家的 tools 格式。技能是「一段提示词加一组工具」，由 Keine 在组装上下文时注入，不依赖任何运行时自带的技能机制。

## 服务商接入

Keine 原生实现两个适配器：OpenAI 兼容接口（Chat Completions）和 Anthropic Messages。后者单独做，是因为 Anthropic 的 OpenAI 兼容层不支持缓存、也不建议用于生产。其他服务商走它们自己的 OpenAI 兼容端点，或者由部署者自选的模型网关（LiteLLM、OpenRouter 等）接入，Keine 只认 base URL，不为单个服务商写适配器。框架和官方 SDK 可以用在适配器内部，或作为循环写法的参考。

## 联网搜索与服务商执行的工具

联网搜索和网页抓取是助手的两项**能力**，不是固定的某个工具。每次运行开始时，按当前模型给每项能力解析出一条路线：

- **服务商自带**：搜索在服务商那边执行（如 Anthropic 的 `web_search`、`web_fetch`）。这是「工具执行归循环」的唯一例外。适配器在能力表里声明自己是否「由模型自主决定调用」并且「能和 Keine 的工具同时使用」，两条都满足才能走这条路线。适配器负责把服务商的搜索过程转成 `activity`、把引用归一成 Keine 的来源格式、把搜索次数计入统一用量；服务商要求原样续传的内容（如 `pause_turn`、加密结果块）只在一次运行的内存里保留，不改变保存的消息格式。
- **Keine 工具**：Keine 自己执行的 `web_search`，背后是可替换的搜索服务适配器（第一版接 Tavily）。

部署者可以按模型指定路线；不指定时，适配器支持服务商自带就走它，否则走 Keine 工具；两条都没有时 AI 功能不启用。第一版：Anthropic 走服务商自带（搜索加抓取），OpenAI 兼容一路走 Keine 工具（只搜索，Keine 自己的抓取工具以后再加，并且只能抓取搜索结果里出现过的 URL）。只能强制搜索的形态（如 OpenAI Chat Completions 的搜索专用模型）和不能与其他工具共存的形态（如 DeepSeek 的内置搜索）不算支持。是否搜索一律由模型决定（`tool_choice: auto`），不强制。

## Considered Options

- **Sidecar（Node 或 Python 进程跑 Vercel AI SDK、Pydantic AI 等）**：服务商覆盖最广，但部署从「一个二进制加 Postgres」变成两套运行时；还要两条内部协议（运行请求和事件中继、工具回调），工具读课程数据要回调 Go，权限要做两遍。服务商覆盖可以靠部署者的网关解决，所以没选。
- **进程内，但由框架管整个循环（如 Genkit `Generate`、Eino Runner）**：少写一个循环，但消息、工具、事件三条边界都要双向转换，进度事件的粒度和每一步的用量计量取决于框架有没有相应的钩子，框架升级可能打破转换层；换框架等于重写这四层转换。
- **会自己持有会话的运行时（ADK Go、LangGraph、Claude Agent SDK）**：历史存在框架自己的格式里，和「存自己的格式」直接冲突；Claude Agent SDK 还不能以 OpenAI 兼容接口为基线。

## Consequences

- 循环本身（几百行）、并行工具调用、错误和超时处理由 Keine 自己写和测。分析和探索对话的每一轮共用同一个循环，区别只在上下文组装和工具集。
- 各家兼容端点的差异（例如流式工具调用的增量格式、不支持并行工具调用）在适配器里吸收；缓存标记、推理内容等只有原生接口才有的能力，要等官方 SDK 跟进或自己实现。
- 运行和网站共用一个进程，靠全局并发上限、单次运行截止时间、每用户同时一个运行来兜底，工具的 panic 要在循环里接住。重启 Keine 会中断进行中的运行。
- 选择服务商自带搜索，是因为它的检索质量通常好于第三方搜索接口；代价是每个服务商的形态都要在适配器里单独吸收（结果格式、引用、计费字段、与函数工具的互斥）。
- 如果探索助手以后需要执行代码或其他需要沙箱的工具，重新评估独立进程。
