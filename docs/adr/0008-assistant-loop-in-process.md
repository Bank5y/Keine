# 探索助手在 Go 进程内运行，工具循环归 Keine，可替换的只有模型适配器

探索助手的工具循环（调模型 → 执行工具 → 回填结果 → 再调模型）写在 Keine 的 Go 服务里，不用 agent 框架的整套循环，也不另起 sidecar 进程。能替换的单位是**模型适配器**：它只负责一次流式调用，把各家的流式增量拼装好，向上交出文本增量、完整的工具调用、统一后的用量（输入、输出、缓存命中、缓存写入）和结束原因。工具执行和权限、运行中的进度事件、轮数上限、截止时间、取消、每一步的用量计量、输出校验都在循环里，由 Keine 决定。这样数据库里的消息、推给前端的事件、工具定义三条边界都是 Keine 自己的格式，换服务商或换框架只动适配器。

## 边界

- **保存的消息**：和服务商无关，角色加 Markdown 内容，元数据记模型、提示词版本和用量，以带格式版本号的 JSON 存储。运行中的工具调用和工具结果只在内存里，不落库；系统提示词不保存原文，只记版本。
- **流式事件**：`POST` 请求，响应为 `text/event-stream`，事件只有 Keine 定义的 `delta`、`activity`、`done`、`error`，服务商的原始片段一律不透传。`delta` 带段名（`title`/`intro`/`body`），可带 `reset` 让前端清空草稿；`activity` 只带结构化的种类、目标和状态，文案由前端拼；`done` 带校验通过的三部分。连接断开即取消运行，已消耗的用量照样计入，第一版不做续接。
- **工具和技能**：工具是 Keine 的 Go 接口（名称、描述、从 Go struct 生成的入参 JSON Schema、`Execute`），只能通过运行上下文（用户、课程、讲、选区）访问数据，权限由 Keine 保证；适配器负责转换成各家的 tools 格式。技能是「一段提示词加一组工具」，由 Keine 在组装上下文时注入，不依赖任何运行时自带的技能机制。

## 服务商接入

Keine 原生实现两个适配器：OpenAI 兼容接口（Chat Completions）和 Anthropic Messages。后者单独做，是因为 Anthropic 的 OpenAI 兼容层不支持缓存、也不建议用于生产。其他服务商走它们自己的 OpenAI 兼容端点，或者由部署者自选的模型网关（LiteLLM、OpenRouter 等）接入，Keine 只认 base URL，不为单个服务商写适配器。例外是**服务商配置**：不是新的适配器，而是挂在通用适配器上的一组默认值和规则（默认地址、思考模式开关、推理内容的回传、用量字段映射、搜索和抓取的路线）。第一版只有 DeepSeek 一份，它是推荐的站点模型；其他服务商（Kimi、MiniMax 等）以后按需求加配置，不加适配器（#112）。框架和官方 SDK 可以用在适配器内部，或作为循环写法的参考。

## 联网搜索与服务商执行的工具

联网搜索和网页抓取是助手的两项**能力**，不是固定的某个工具。每次运行开始时，按当前模型给每项能力解析出一条路线：

- **服务商自带**：搜索在服务商那边执行（如 Anthropic 的 `web_search`、`web_fetch`）。这是「工具执行归循环」的唯一例外。适配器在能力表里声明自己是否「由模型自主决定调用」并且「能和 Keine 的工具同时使用」，两条都满足才能走这条路线。适配器负责把服务商的搜索过程转成 `activity`、把引用归一成 Keine 的来源格式、把搜索次数计入统一用量；服务商要求原样续传的内容（如 `pause_turn`、加密结果块）只在一次运行的内存里保留，不改变保存的消息格式。
- **Keine 工具**：Keine 自己执行的 `web_search` 和 `web_fetch`，背后是可替换的搜索服务适配器（第一版接 Tavily 和 DeepSeek Search / Fetch API）。服务商的独立搜索接口归在这一条：它由 Keine 调用，和模型 key 是同一把也没关系。

部署者可以按模型指定路线；不指定时，适配器支持服务商自带就走它，否则走 Keine 工具；两条都没有时 AI 功能不启用。第一版：Anthropic 走服务商自带（搜索加抓取）；DeepSeek 配置走 Keine 工具，搜索和抓取都接 DeepSeek 的 Search / Fetch API，用模型那一把 key，不需要 Tavily；其他 OpenAI 兼容模型走 Keine 工具接 Tavily，只有搜索。`web_fetch` 只能抓取本次运行的搜索结果里出现过的 URL。只能强制搜索的形态（如 OpenAI Chat Completions 的搜索专用模型）和不能与其他工具共存的形态（如 DeepSeek 的内置搜索：和函数工具一起声明时，非思考模式返回 400，思考模式请求能通过但模型不调用它，#99 实测）不算支持。是否搜索一律由模型决定（`tool_choice: auto`），不强制。

## 最终答案和输出格式

以「没有工具调用的那一步」为最终答案。探索文档用 `<exp_title>`、`<exp_intro>`、`<exp_body>` 三个标签包裹，循环里的流式解析器逐字切分：标签外的说明文字不推送、不保存，标签内的内容按段推 `delta`；某一步写了标签却以工具调用结束时，这份草稿作废并发 `reset`。结束时按标签校验（三段闭合、标题和简介非空、长度硬上限），不合格时：正文还没流出就自动补一次不带工具的调用，已经流出就报错交给读者重试。步数上限计的是带工具的调用次数，用完后执行完最后一批工具调用，再发一次不带工具的作答调用，保证读者总能拿到文档。

没有用服务商原生 JSON Schema（DeepSeek、智谱没有，Anthropic 上与引用冲突），也没有用「提交结果工具」（最新 Claude 模型和智谱不能强制工具调用，正文放进 JSON 字符串后逐字流式要增量解析转义），也没有用「研究和作答分两次调用」（每次多一次调用，Anthropic 缓存失效）。依据见 `research/structured-output` 分支的调研报告。

## 未固定的第一轮

分析成功结束（发出 `done`）后，这一轮注入了上下文的请求消息（快照）、最终回复和校验通过的三部分暂存在进程内存里，`done` 带一个随机、不透明的分析 ID。固定时前端只提交这个 ID，服务端核对归属（本人、这一讲）并重新检查不与已有探索重叠，然后在一个事务里写入探索、探索文档、快照和第一轮回复，并删除暂存。前端提交不了请求消息、回复或三部分：这些内容会进入以后每一轮的上下文，而服务商的接口不会分辨历史里的助手轮次是不是伪造的。

每个用户只保留一份：新的分析一开始就替换旧的（重试也算新的运行）。出错、输出不合格或中途断开的运行不暂存。暂存从 `done` 起保留 30 分钟，到期或被替换后固定返回 `analysis_expired`，悬浮框保留内容并提供重试；关闭悬浮框不需要另发丢弃请求。重启 Keine 会丢掉所有未固定的第一轮，代价和流式中断一样。这修改了 #74「分析结果不在服务端缓存，固定时由前端提交三部分」的约定。没有用 Postgres 暂存表（要多一张表和定时清理，还会在库里留下读者以为没保存的内容），也没有用前端整段回传或签名令牌（几十 KB 的快照来回传，明文回传还能被篡改）。依据见 `research/unpinned-first-turn` 分支的调研报告。

## Considered Options

- **Sidecar（Node 或 Python 进程跑 Vercel AI SDK、Pydantic AI 等）**：服务商覆盖最广，但部署从「一个二进制加 Postgres」变成两套运行时；还要两条内部协议（运行请求和事件中继、工具回调），工具读课程数据要回调 Go，权限要做两遍。服务商覆盖可以靠部署者的网关解决，所以没选。
- **进程内，但由框架管整个循环（如 Genkit `Generate`、Eino Runner）**：少写一个循环，但消息、工具、事件三条边界都要双向转换，进度事件的粒度和每一步的用量计量取决于框架有没有相应的钩子，框架升级可能打破转换层；换框架等于重写这四层转换。
- **会自己持有会话的运行时（ADK Go、LangGraph、Claude Agent SDK）**：历史存在框架自己的格式里，和「存自己的格式」直接冲突；Claude Agent SDK 还不能以 OpenAI 兼容接口为基线。

## Consequences

- 循环本身（几百行）、并行工具调用、错误和超时处理由 Keine 自己写和测。分析和探索对话的每一轮共用同一个循环，区别只在上下文组装和工具集。
- 各家兼容端点的差异（例如流式工具调用的增量格式、不支持并行工具调用）在适配器里吸收；缓存标记、推理内容等只有原生接口才有的能力，要等官方 SDK 跟进或自己实现。
- 运行和网站共用一个进程，靠全局并发上限、单次运行截止时间、每用户同时一个运行来兜底，工具的 panic 要在循环里接住。重启 Keine 会中断进行中的运行。
- 选择服务商自带搜索，是因为它的检索质量通常好于第三方搜索接口；代价是每个服务商的形态都要在适配器里单独吸收（结果格式、引用、计费字段、与函数工具的互斥）。
- 如果探索助手以后需要执行代码或其他需要沙箱的工具，重新评估独立进程。
