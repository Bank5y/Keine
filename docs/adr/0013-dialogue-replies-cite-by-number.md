# 探索对话的回复用编号引用资料，链接由系统生成

读者在探索对话里请助手「找几篇相关的论文并给出链接」，拿不到任何链接：`followup.md` 要求回复不写链接、「来源由系统记录」，`CheckReply` 把链接当作错误（#141）；系统确实在每一轮的元数据里记下了搜到和读过的网页，界面却不显示。

我们放开探索对话回复里的链接，但不让模型写地址。给模型的搜索结果和网页带编号，回复里只写 `[n]`，系统把它换成记录下来的真实链接；对不上的编号直接去掉。编号在整个探索对话（整棵树）里共用，同一个网址只有一个编号；一轮能引用的只有沿祖先链和本轮记下的资料，因为模型只看得到这些。只看过摘要的搜索结果也可以引用：保证的是链接真实、模型见过，不保证内容读过全文。

取舍的依据是：作为对话里的信息来源，链接的确信度比能给出多少链接更重要。读者点开一个不存在的论文链接，损失的是对整个探索助手的信任。

## Considered Options

参照了七个开源项目的源码（2026-11-24 的 HEAD）：

- **编号引用，系统换链接**：Onyx（`f9b2636`，`backend/onyx/chat/citation_processor.py`，查不到的编号丢弃）、Perplexica（`348feca`，`src/lib/hooks/useChat.tsx`，`[n]` 换成 `sources[n-1]`，没有就换成空串）、Open WebUI（`0666e59`，`backend/open_webui/config.py` 的 RAG 模板和前端 `citation-extension.ts`）。我们选了这一类。
- **模型直接写 Markdown 链接，只靠提示词约束**：codex（`f64f003`）、DeepSeek Harness（`4b399c39`，`packages/web/tool-web/src/search.ts` 把结果格式化成 `[标题](url)` 并要求「cite the relevant URLs as markdown links」）、gpt-researcher（`9d39a2f`）、open_deep_research（`1b7d2e8`）。都没有事后校验，编造的地址会原样显示。
- **模型写链接，服务端对照记录下的网址校验，对不上的降成纯文字**：七个项目里都没有先例；模型更顺手，但校验要我们自己维护，标题和地址还可能错配。

## Consequences

- 只放开探索对话的回复。分析生成的探索文档（概念解释）仍然不能有链接，探索报告的参考仍由系统生成。
- `CheckReply` 继续把回复里的地址当作错误；`[n]` 是允许的写法。
- 回复里的引用显示成网站域名加编号的标签，悬停看标题；不是上标数字。
- 没有联网搜索可用时，助手说明这次没法查找，只给名称，不给链接。
- 专门的学术论文检索工具没有做，留作后续。
