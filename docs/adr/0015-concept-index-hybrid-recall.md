# 概念索引改为概念加段落的混合召回，嵌入可选

ADR 0011 的「先作答，再关联」不变，变的是第 2 步召回候选的方式。原来只拿各讲独立抽取的概念名和别名，对回答做字符串匹配，候选里大多是「工具」「推理」这类泛词。在一门真实课程（50 讲）上做的原型里，按回答召回的 recall@5 只有 0.28。

我们改成两路召回，用 RRF 融合，每讲最多一个候选，取前 5：

1. **合并后的概念**：逐讲抽取之后，在课程级合并同名的概念和别名（只合并「名~名」「名~别名」，避免链式误合并），为每个概念选出主讲解处，并排除泛词（出现在 35% 以上讲里的概念）。
2. **段落 BM25**：把小节切成段落（中文按字切二元组，英文按词），对回答打分。这一路是确定性的，课程版本一产生就建立，不依赖模型抽取。

管理员的修订挂在课程上，召回时叠加，改完立即生效、不必重建。权重是概念这一路 RRF 分数上的四档倍数：降低 ×0.5、默认 ×1、提高 ×2、优先 ×4；不做强制置顶，以免多个「必选」同时命中时挤掉其余候选。

关联的目标从「概念条目」改成「小节」。候选的标签取命中的概念名，没有概念时取小节标题。

语义召回（嵌入）做成全站可选的一项，分三档：关闭（默认）；本地（在 Go 进程内运行 ONNX 小模型，模型由管理员在后台下载，不打包进镜像）；外部（OpenAI 兼容的嵌入 API）。原型里，两路加嵌入的 recall@5 是 0.57，不加嵌入、只按问题做 BM25 是 0.43。向量存在 Postgres 的普通列里，查询时在内存里算相似度，不用 pgvector。

## Considered Options

- **作答前检索注入（RAG）**：盲评平均 2.8 分，「先作答、再关联」是 3.5 分。第 1 轮的回答常被跑题的检索结果带偏，ADR 0011 否决它的理由依然成立。
- **给模型一个按需查索引树的工具（PageIndex 式）**：盲评平均 2.6 分，输入 token 是 RAG 的 7 倍多。
- **嵌入走独立的服务容器（TEI/Ollama）**：多一个部署组件。只有本地 ONNX 跑得太慢时，才作为「本地」这一档的退路。
- **Postgres 扩展做全文检索（pg_bigm / ParadeDB）**：要换数据库镜像，而一门课只有几百段，进程内打分已经够用。

## Consequences

- 新版本一发布就有段落关联可用；模型抽取仍由管理员手动触发，费用记在站点上。
- 换嵌入模型或嵌入提供方后，已有向量全部失效，需要按课程重新嵌入。
- 索引上记下抽取提示词的版本和模型。跨版本复用一讲的条目，条件是正文和提示词版本都相同。
