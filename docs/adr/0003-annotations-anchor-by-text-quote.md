# 标注按原文片段加前后文定位，并永久保留旧版正文

标注记录的是选中的原文片段，以及它前后各一小段文字（与 W3C TextQuoteSelector 和 Hypothesis 的做法相同），不记录字符偏移或 DOM 路径。课程更新会整体替换一讲的 Markdown，偏移和 DOM 路径在任何改动之后都会失效；按原文片段定位的话，没改到的段落里的标注可以自动对回原位。对不回去的标注进入标注迁移：系统用确定性的模糊匹配（diff-match-patch / Bitap 加上前后文打分）给出建议位置，用户确认或手动指定。实际的魔棒没有引入 diff-match-patch 库，而是手写了编辑距离搜索（Sellers 算法），再按前后文和原位置打分，用意相同：同样的输入总给出同样的建议。为了让迁移页能左右对照，每次课程更新改动了正文的讲，旧版正文都会永久保留一份。正文修订本来就不频繁，存储成本可以忽略。

## Considered Options

- 按字符偏移或 DOM 路径定位：实现简单，但任何一次正文改动都会让后面的标注全部错位。
- 迁移时用 AI 匹配：系统是自托管的，没有 AI 配置，结果也不可预期。以后可以作为另一种「魔棒」实现接进来。
- 只在有待迁移标注时才保留旧版正文：省存储，但引入了引用计数和清理逻辑，而且以后有人在旧版正文上补标注时就没有依据了。

## Consequences

- 标注本身要存原文片段和前后文，即使正文找不到它，也能作为原文摘录显示。
- 课程更新流程要比较每讲新旧正文；有改动就写入旧版正文，并对受影响的标注重新定位。
