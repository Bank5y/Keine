# AI 额度用积分：按真实用量和费率换算，自带模型完全绕开

分析和探索对话用的是部署者的 key，注册又默认开放，所以要有按用户的额度。我们不按运行次数计，而是用积分：每次运行的统一用量（输入、缓存命中、缓存写入、输出、搜索次数）乘以部署者按模型配置的费率，用户属于管理员分配的套餐，每天 0 点重置成套餐的每日额度、不结转。读者也可以接入自带模型，这类运行不扣积分、不写用量明细，也不能使用部署者付费的 Tavily 搜索，只用服务商自带的搜索或读者自己填的 key；这样「自带模型不碰部署者的钱」能严格成立，Keine 不必为它计量。

## Considered Options

- 按运行次数计：读者最好懂，也不依赖适配器能不能拿到用量；但一次长运行（完整正文、多步搜索）和一次短运行同价，和成本脱钩。
- 积分之外再设全站每日总闸：部署者的总成本已经约等于所有用户每日额度之和，新用户的默认套餐可以设为 0，不需要第二层。
- 自带模型免费用部署者的 Tavily（Open WebUI、LobeChat 的做法）：部署者要为不记录的调用付钱。

## Consequences

- 每次运行在一张独立于消息的用量明细里记一行（不存正文）；不固定的分析不落库，消息元数据覆盖不到它们。服务商不报的项记为空而不是 0，拿不到用量（如中途断开）时按本地估算并标记。剩余积分由每日额度减去当天明细合计得出，0 点重置不需要定时任务。
- 分析开始前预估积分，不够就不生成（`credits_insufficient`），通过后按实际扣、允许透支；探索对话不预估，扣到 0 就取消并保留已流出的回复，标记为中断（`credits_exhausted`）。
- 「部署者配好 AI 后用户无需额外开通」变成取决于默认套餐的每日额度。
- 自带模型的运行管理员看不到用量，但仍受全局并发上限、每用户同时一个运行和单次运行截止时间约束。

## 补充：自带模型的接入与安全边界（#111）

自带模型由部署者用一个全站开关决定是否开放，默认关；开放的前提是配置了加密主密钥。每个读者最多一份配置（接口格式、地址、key、模型名、上下文长度），格式只有 OpenAI 兼容和 Anthropic Messages 两种，复用 ADR 0008 的两个适配器；另外可以直接选已适配的服务商（第一版只有 DeepSeek），套用它的服务商配置，只需填 key 和模型名（#112）。读者打开「使用自带模型」后，每次运行**开始时**读取当时的设置决定走自带模型还是站点模型；节点和轮次不绑定模型，同一节点里可以前后换模型。删除配置会同时关掉这个开关。运行出错时不自动退回站点模型（那会在读者不知情时扣部署者的积分），报 `own_model_error`。

- **key 的存储**：模型 key 和读者自填的 Tavily key 用部署者的主密钥加密存库，写入后不再返回前端，只显示末 4 位；管理页看不到 key、地址和模型名，消息元数据只记 `source: own` 和模型名。加密防的是只拿到数据库的人，防不了部署者：请求从服务端发出，运营服务器的人技术上一定能拿到明文，界面如实说明。没有选「浏览器直连模型、key 不经服务端」，因为工具循环和课程工具都在服务端（ADR 0008），且多数服务商不允许浏览器跨域调用。
- **SSRF**：服务端会请求读者填的任意地址，检查放在拨号阶段、对每次连接实际解析出的 IP 判断（同时挡住 DNS 重绑定），不跟随重定向，错误只回类别不回显对方响应。默认只允许公网 https。部署者可用一个网段白名单放行内网地址，白名单内允许 http，以支持本机或局域网里的模型（如 Ollama）；云元数据地址无论如何都拦。没有选「一个开关放开所有内网」，因为注册默认开放，任何注册用户都能借服务端探测内网。
- **验证**：保存前必须通过一次带假工具的流式请求（认证、流式、带工具不被拒绝），因为两种轮次都依赖工具；Tavily key 保存前做一次真实搜索。
- **能力**：上下文长度由读者填写（默认保守值），用于判断正文是否超长；其他能力按格式取保守默认，OpenAI 兼容不开并行工具调用、不加缓存标记，Anthropic 加缓存标记。
- **联网搜索**：读者在「服务商自带」（仅 Anthropic 格式，读者自行确认对方支持）、「Tavily（自填 key）」、「不联网」中选；选了已适配的服务商时多一项「服务商搜索」（DeepSeek 用读者自己的 key 调 Search / Fetch API，不用再填），默认仍是不联网；不联网时助手只用课程工具，界面提示未联网。
