# 媒体文件按类型分流到对象存储，配置放在后台

ADR 0001 只规定课程文件通过一个可替换的存储接口读写，至于用本地磁盘还是 S3，由部署时的环境变量决定，而且只能二选一：所有文件要么都在本地，要么都在桶里。实际情况是，占空间、占带宽的是视频，图片其次；文字稿和课程清单又小，又被阅读、编辑、概念索引频繁读取，放在本地最快。

所以我们改用**分流存储**（`storage.Routed`）：本地磁盘一直在，视频（可选：再加上图片）在对象存储连上并启用后写进桶里，其余文件一律留在本地。读取时先按类型去它该在的那一侧找，找不到再去另一侧找。下面几种情况都靠这条回退照常可读：对象存储启用之前上传的视频、同步留下的本地副本，以及旧部署把所有文件都放进桶里的情况。写入一个文件时，会顺手删掉另一侧的旧副本，以后切换上传范围就不会读到过期的内容。

对象存储的设置（连接参数、上传范围、访问方式）存在 `settings` 表里，由管理员在后台修改，保存时先连一次，连不上就不保存。环境变量 `KEINE_STORAGE`、`KEINE_S3_*` 只给出管理员第一次保存之前的初始值。默认部署自带一个 RustFS，`KEINE_STORAGE` 默认值为 `s3`，所以新部署开箱就把视频放进对象存储。Secret Key 用主密钥加密后存库；没有主密钥时，只能用环境变量里的密钥。

浏览器访问媒体文件有三种方式：由服务器代理；跳转到 Presign 地址；跳转到 CDN 上的地址。无论哪种方式，都由 Keine 先检查权限，再给出地址。文件还在本地的、HLS 播放列表（片段地址是相对的，签名带不过去），以及 SVG（不能离开沙箱策略），始终由服务器转发。

迁移工具在本地和桶之间搬运已有的文件：推送（移到桶里，删掉本地副本）、同步（复制到桶里，保留本地副本）、拉取（复制回本地，桶里不删）。目标端已有、且大小相同的文件会跳过，所以中断后可以重跑。

## Considered Options

- **保持二选一，只把配置搬进后台**：改动最小，但文字稿也要走网络读取，而且想先迁一部分文件就做不到。
- **按课程而不是按文件类型分流**：可以「这门课在云上」，但一门课里绝大部分体积都是视频，按类型分流更直接，也不用多维护一张表。

## Consequences

- 对象存储连不上时，服务照常启动，新文件写到本地，后台显示错误；只有已经推送到桶里的文件暂时读不到。
- 启用对象存储后，媒体文件的每次读取可能多一次 HEAD 请求（Presign/CDN 要先确认对象在桶里，回退时要先查第一侧）。
- 迁移任务在进程内后台运行，一次只能跑一个，重启后进度不保留，但可以重跑。
